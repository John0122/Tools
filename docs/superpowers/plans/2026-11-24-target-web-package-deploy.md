# Target Web 打包与部署实施计划

> 使用 `superpowers:executing-plans` 在当前会话实施；权限以仓库规范和本次用户指示为准。

**目标：** 恢复 `38080:8080`，保留 `38443:8443`，提供双镜像离线打包与目标机器部署入口。

**结构：** `package.sh` 复用 `build.sh`，导出同标签、同 Linux 架构的两个镜像及必要运行文件；`deploy.sh` 校验离线包和目标架构，导入镜像后复用 `target_web.sh up --no-build`。证书在目标机器生成，局域网 IP 沿用部署输入提示。

**技术：** Bash 3.2、Docker/Compose、tar、SHA-256、现有 OpenSSL/AWK；无新增依赖。

**依据：** 本次恢复端口与新增脚本指示、`target_web/README.md` 和外链检测设计。

## 约束

- 前端仍为一个镜像，后端仍为一个镜像；Go 8000 不发布。
- 默认镜像标签 `local`，支持 `--version` 和 `--arch amd64|arm64`；不代替正式发布版本决策。
- 默认输出 `target_web/dist/target-web-<标签>-linux-<架构>.tar.gz`；已有同名包拒绝覆盖。
- 白名单打包运行文件，不包含源码、开发缓存、现有证书和私钥。
- 打包脚本支持 `--no-build` 导出已有镜像；部署无需 Go，不联网拉取业务镜像，不修改 hosts、代理或证书信任。
- 检查范围为基础语法、格式、静态检查和 Go 编译；单元测试、实际打包、镜像构建和服务验证需另行授权，提交与推送按用户明确指示执行。

## 审查重点

- 标签无效、镜像缺失或两个镜像平台不一致：打包在导出前失败。
- 包损坏、元数据缺失、目标机器架构不匹配：部署在导入和重建服务前失败。
- 导入后标签对应的镜像 ID 不符合包内记录：不启动服务。
- 路径包含空格、命令失败或收到中断：保留原有包，仅清理本次临时目录。
- HTTP 来源恢复后仍精确限制端口；HTTPS 页面禁止连接明文 WS。
