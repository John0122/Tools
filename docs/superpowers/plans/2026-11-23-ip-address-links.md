# IP 地址链接分类实施计划

> 使用 `superpowers:executing-plans` 按已确认方案实施；权限以仓库规范和本次用户授权为准。

**目标：** 新增 `/links/ip-address/`，分别展示内站、公网外站和局域网其他设备的 IPv4 链接。

**结构：** 复用页面生成器、分类导航和现有样式。前端启动时注入本站 IP 及两个可选 HTTP(S) 入口，静态 HTML 与样例清单同时更新。

**技术：** 原生 HTML、Python 生成器、POSIX Shell/AWK、Docker Compose，不新增运行依赖。

**依据：** `docs/superpowers/specs/2026-11-23-link-lab-design.md` 及用户已确认的新增分类方案。

## 约束

- 当前站点 IP 优先归内站；外站限定公网 IP；局域网限定其他设备的 RFC 1918 私有 IP。
- 本站使用 `TARGET_WEB_HOST`；可选入口为 `TARGET_WEB_PUBLIC_IP_ORIGIN`、`TARGET_WEB_LAN_IP_ORIGIN`，格式为 `http(s)://IPv4[:端口]`。
- 未配置的入口显示说明，清单目标为 null；公网和局域网目标的响应状态不做固定承诺。
- 内站提供真实 HTTP/HTTPS、隐藏链接、404/410 对照；IP 分类不复用域名外站样例。
- 仅执行基础语法、格式检查；单元测试可以编写，本次不运行。服务、浏览器验证及提交推送遵循独立授权。

## 复核重点

- 空配置不产生错误 href，也不把未配置链接标成 HTTP 200。
- 公网入口拒绝私网、回环、共享地址、文档地址、链路本地、多播与保留地址。
- 局域网入口只接受私有地址，公网和局域网入口都不能重复本站 IP。
- URL 不允许域名、认证信息、路径或查询参数；端口范围为 1–65535。本站字段单独限制为裸 IPv4，不能带端口或末尾斜杠。
- 链接在服务端注入，不依赖浏览器 JavaScript；导航与生成清单一致。
