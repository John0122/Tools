# IP 地址链接分类实施计划

> 使用 `superpowers:executing-plans` 按已确认方案实施；权限以仓库规范和本次用户授权为准。

**目标：** 新增 `/links/ip-address/`，分别展示内站、公网外站和局域网其他设备的 IPv4 链接。

**结构：** 复用页面生成器、分类导航和现有样式。公网链接固定为完整诊断 URL；宿主机部署时提示输入局域网设备 IP，前端启动时注入本站 IP 与局域网入口，静态 HTML 与样例清单同时更新。

**技术：** 原生 HTML、Python 生成器、POSIX Shell/AWK、Docker Compose，不新增运行依赖。

**依据：** `docs/superpowers/specs/2026-11-23-link-lab-design.md` 及用户已确认的新增分类方案。

## 约束

- 当前站点 IP 优先归内站；外站限定公网 IP；局域网限定其他设备的 RFC 1918 私有 IP。
- 本站使用 `TARGET_WEB_HOST`；公网固定为 `https://1.1.1.1/cdn-cgi/trace`，保留完整路径。
- `up` 未配置局域网入口且有交互终端时提示输入另一套服务的私有 IPv4；回车跳过，非法输入重试，输入流中断则取消。默认入口为 `https://<IP>:38443/`；`--lan-ip` 仅用于 `up`，优先于已有 `TARGET_WEB_LAN_IP_ORIGIN`。
- 局域网入口环境变量继续支持 `http(s)://IPv4[:端口]`；非交互且未配置时跳过，不阻塞部署。输入不持久保存。
- 局域网未配置时显示说明，清单目标为 null；公网和局域网目标的响应状态不做固定承诺。
- 内站提供真实 HTTP/HTTPS、隐藏链接、404/410 对照；IP 分类不复用域名外站样例。
- 仅执行基础语法、格式检查；单元测试可以编写，本次不运行。服务、浏览器验证及提交推送遵循独立授权。

## 复核重点

- 空配置不产生错误 href，也不把未配置链接标成 HTTP 200。
- 公网链接的 `/cdn-cgi/trace` 路径在页面和清单中保留，不被根地址替换截断。
- 局域网入口只接受其他设备的私有地址；输入错误在证书生成和镜像构建前反馈。
- 局域网入口环境变量不允许域名、认证信息、路径或查询参数；端口范围为 1–65535。本站和 `--lan-ip` 字段限制为裸 IPv4，不能带端口或末尾斜杠。
- 链接在服务端注入，不依赖浏览器 JavaScript；导航与生成清单一致。
