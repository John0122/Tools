# Target Web Link Lab Implementation Plan

> **For agentic workers:** 使用 `superpowers:executing-plans` 按本计划实施，提交与推送遵循仓库规范及用户当次指示。

**Goal:** 交付 1 个目录页、13 个分类测试页及实际服务端行为，包含 IP 地址分类与暗链、死链。

**Architecture:** 原生静态页面由 Nginx 托管；Go `/lab/` 提供交互协议；独立外站主机名复用现有双镜像与端口。

**Tech Stack:** HTML/CSS/JavaScript、Go 1.26、Nginx、Docker Compose。

**Spec:** `docs/superpowers/specs/2026-11-23-link-lab-design.md`

## Global Constraints

- 后端内部 8000，前端仅发布 `38443:8443`；HTTP 8080 保留容器内部健康检查，仍为两个镜像、两个容器。
- 分类数为 13，所有运行响应真实；暗链/死链是预置演示数据，IP 分类中的非受控目标不预设响应状态。
- 不自动修改系统 DNS、hosts 或证书信任；仅安装已明确获准的两项 Go 依赖。
- 静态资源进前端镜像，后端镜像仍只含静态二进制及公共 CA。

## Review Focus

- HTTPS 来源、证书与外站主机名在配置变化后保持一致，WebSocket 使用 WSS。
- 404/410 不被静态回退、CORS 或页面错误处理掩盖成成功。
- 原始 HTML 中真实存在资源与链接；动态请求、隐藏样例和清单的预期一致。
- WebSocket 在反向代理和服务关闭时能结束，不遗留无限连接。
- 媒体、字体、下载文件是真实格式，第三方素材保留许可证与来源。

## 实现约定

- 沿用现有主题与普通导航；资源样例生成脚本用于准备演示数据。
- 协议依赖为 graphql-go/graphql v0.8.1 与 coder/websocket v1.8.15。
- 页面与清单包含 13 类、142 条记录，不包含未发布的内站 HTTP 和外站 WS 入口。预连接和 DNS 提示不虚构 HTTP 状态，清单用 null 表示；公网固定为 `https://1.1.1.1/cdn-cgi/trace`，局域网 IP 目标未配置时 target 为 null，两者均不预设响应状态。
- 资源链接使用新标签页，文件按浏览器下载行为处理。
- 相对跳转保留外部端口；WebSocket 各连接独立持有超时计时器。
