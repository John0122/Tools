# target_web 设计

- 目标：在 `target_web/` 提供可用 Docker 启动的基础 Web 靶机，通过宿主机 HTTP `38080` 与 HTTPS `38443` 提供外部入口。
- 范围：访问页、`/healthz`、Docker Compose、启动脚本和中文说明。尚未指定业务流程或漏洞场景，本次采用基础连通性靶机作为实现默认值。
- 证书：参考 `FutureConsole/deploy/lib/cert.sh`，使用 OpenSSL 生成 ECDSA P-256、命名曲线、自签名服务器证书，有效期 825 天；SAN 包含宿主机 IPv4、`localhost`、`127.0.0.1`。私钥权限为 600，运行时文件不入库。
- 地址：启动脚本按默认路由检测 macOS/Linux 宿主机 IPv4，支持 `--host` 指定；检测失败时明确报错。检测在宿主机进行。
- 方案：Nginx 前端与 Go 后端分别运行于独立容器；前端发布 `38080:8080` 与 `38443:8443`，8080 同时用于健康检查，后端 8000 不发布。前端使用 `nginx:1.31-alpine-slim`，证书在宿主机生成并只读挂载。
- 离线分发：`package.sh` 复用 `build.sh`，按 `amd64`/`arm64` 导出两个同标签镜像、必要运行文件、元数据及 SHA-256 清单到 `dist/`；拒绝覆盖已有包，私钥和源码不随包分发。`deploy.sh` 在目标机器校验完整性、平台及导入后的镜像 ID，复用 `target_web.sh up --no-build` 启动；目标机器不需要 Go，不拉取业务镜像，沿用局域网 IP 输入提示并在当地生成证书。
- 生命周期：有效且匹配的证书复用；证书缺失、密钥不匹配、访问 IP 不匹配或剩余不足 30 天时重建。启动时重建容器以载入证书。停止保留证书。
- 验证：实际生成证书，验证 SAN、签名算法、复用及更换行为；构建并启动 Docker，检查两个公开映射、HTTP 请求以及使用证书校验的 HTTPS 请求。
