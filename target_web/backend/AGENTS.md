# AGENTS

## 技术栈

- 后端使用 Go 标准库 `net/http`，版本以本目录 `go.mod` 的 `go` 指令为准；当前不引入路由框架、数据库或 ORM。
- GraphQL 与 WebSocket 分别使用已获准的 `github.com/graphql-go/graphql`、`github.com/coder/websocket`；版本锁定在 `go.mod`/`go.sum`。
- 只提供 API 与健康检查，不托管前端文件，不加载 TLS 证书；内部 HTTP 默认监听 8000，由前端 Nginx 反向代理，Docker 不发布后端宿主机端口。
- `../build.sh` 在本机以 `CGO_ENABLED=0 GOOS=linux GOARCH=<目标架构>` 交叉编译；Dockerfile 使用只含二进制的临时目录组装 `scratch` 运行镜像，只加入公共 CA 证书，不包含源码、Go 工具链、前端文件或本机 IP 私钥。
- 无 shell 的运行镜像通过 `/server healthcheck` 检查实际 `http://127.0.0.1:8000/healthz` 响应。

## 接口与权限

- 接口明确输入、输出和错误语义；调整已有接口时说明兼容性影响。
- 服务端校验请求参数；引入认证或多用户数据时，同步校验访问权限和数据归属。
- 方法目录与描述接口保持一致。HEAD 不返回正文；CONNECT 描述接口返回 501，不建立隧道；TRACE 不回显请求头或认证信息。
- `/api/invoke` 仅代发 TRACE、CONNECT，目标由实际监听地址与固定路径生成；不得接受客户端传入的地址、路径或认证头，不使用环境代理，不跟随重定向。
- 代发结果保留目标响应的状态码、响应头及正文，不用预置数据模拟请求；入口状态与目标状态分开表示。
- `internal/linklab` 负责 `/lab/` 的 REST、GraphQL、表单、WebSocket、固定重定向及 404/410；不开放任意代理或跳转地址，不保存演示提交内容。
- CORS 与 WebSocket Origin 按 `TARGET_WEB_HOST`、`TARGET_WEB_EXTERNAL_HOST` 和本机回环地址的 HTTP 38080、HTTPS 38443 入口精确匹配；拒绝其他协议与端口组合。JSON/表单请求体上限 16 KiB，WS 消息上限 4 KiB、连接最多 2 分钟；关闭服务时释放升级连接。

## 代码与数据

- 按职责组织服务启动、请求处理与代发逻辑，按实际复杂度拆分。
- 当前描述接口不保存请求体、不修改或删除业务数据；增加有状态行为时明确说明影响并同步接口文档。
- 如引入 SQL，使用参数化查询；多步写操作明确事务边界，可能重复执行的写操作明确幂等规则。

## 配置与日志

- 配置与代码分离，凭据不明文入库（须入库时加密保存），示例配置使用占位值。
- 日志标明操作位置和请求方法、路径，不记录密码、令牌、Cookie 等敏感数据；对外错误不暴露内部堆栈。
- `/healthz` 的外部协议取自入口 Nginx 覆盖的 `X-Forwarded-Proto`；后端保持只在容器网络内暴露，避免客户端直接伪造入口信息。

## 外部调用

- 网络调用设置超时，重试限定次数并确保操作可安全重复。
- 代发请求绑定入站请求上下文，并限制请求体及响应体大小。

## 验证与命令

- 以下基础检查在本目录执行：格式检查 `gofmt -l .`（无输出为通过）、静态检查 `go vet ./...`、构建 `go build ./...`。
- 可提交：纯函数单元测试，以及通过 `httptest`、本机临时监听器进行的请求处理与服务生命周期测试（与源码同目录，`_test.go`）；不连接外部业务服务。
- 后端测试命令为 `go test -race ./...`；运行授权遵循根目录规范。
